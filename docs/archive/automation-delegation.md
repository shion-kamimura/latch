# 自動実装の責務と標準機能への委譲

> 状態: #64時点の移行・責務置換の記録。現行の全体方針は [ハーネス設計](../harness/design.md)、構成は [アーキテクチャ](../../ARCHITECTURE.md) を参照してください。以下のIssue操作・残項目は当時の記録です。

## 移行時の決定

#64で #53 / PR #58の「OpenCode＋既存独自境界」方針を更新し、公式OpenCode GitHub連携＋通常PR＋通常PR CIへ移行します。独自のエージェントループ、publisher、本文レンダラー、検証再実行器、無人修復ループを保守しません。新規有料SaaS・常駐サーバー・複数モデル切替層は導入しません。

| 旧責務・ファイル                                                 | 置換・廃止・残存処理                                                                                                                                      |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prepare.mjs`、`policy.py`、prepare job                          | 削除。Issue/PR取得は公式連携。新workflowの小さなauthorizeステップだけがコマンド・現在権限・再実行者・開いた同一repoのPRを確認する。旧request schemaは不要 |
| `run.py`、`agent_metrics.py`、agent Dockerfile                   | 削除。実装・ツール反復・自己テストは公式Action。実行時間・直列化はActions。旧コンテナ境界・候補収集・独立検証は残さない                                   |
| `registry.py`、依存smoke、store受け渡し                          | 削除。#55の依存整合・キャッシュの目的はpnpm frozen install・Actions cacheとhead準備指示へ引き継ぐ。旧コンテナstoreの実装は移植しない                      |
| `gateway.py`、gateway Dockerfile                                 | 削除。DeepSeekへ公式providerから直接接続。旧5 USD費用予約・通信量・tokenizer境界とキー分離は維持しない。差分・監視・停止を運用手順に明記                  |
| `publish.py`、公開job                                            | 削除。公式のbranch/commit/通常PR作成・同じPRへの追加修正を採用。hashブランチ・所有マーカー・proposal schemaの完全互換は不要。人の変更保持・非forceを指示  |
| proposal・diagnostics artifact、専用再実行                       | 廃止。CIの結果は通常PRのChecks・Actionsログ。CIのみ再実行はGitHub標準機能                                                                                 |
| `.github/automation/` の旧テストとsmoke、`automation-checks.yml` | 参照先と共に削除。現行の起動制御をVitestでモック検証し通常CIへ含める。旧経路を並行保守しない                                                              |
| `issue-draft-pr.yml`                                             | 削除。コメント起点の `opencode.yml` に置換。`workflow_dispatch` による旧起動は終了                                                                        |
| PR本文・タイトル                                                 | 既存テンプレート・AGENTS・OpenCode指示を利用。最終回答と短いタイトル要約をAIが作成。未実行CIを成功としない。独自本文合成や結果同期は追加しない            |
| `.github/workflows/ci.yml`                                       | 既存の通常PR CIを継続。App作成PR・追加commitから起動する認証構成を採用し、実連動は別途確認                                                                |

実行者権限の薄い接続以外の独自実行基盤は廃止します。旧経路の最終受け入れ条件をすべて実装したという意味ではありません。外部へ委譲したAI出力や自己テストは、要件全体の充足の証明ではありません。

## 関連Issueの置換と非対象

#64の実装PRでは #64・#35・#37・#38・#56・#57・#63をそれぞれCloses指定します。デフォルトブランチへのマージで閉じ、移行途中には手動で閉じません。

- #35: 旧runの隔離依存準備を終了し、pnpm/公式連携と通常CIへ置換。旧隔離保証を実装済みとはしない。
- #37: 旧prepare/publishのDraft所有権・再実行を終了し、公式PR操作へ置換。人の変更を破壊しない指示と競合時の停止を引き継ぐ。
- #38: 旧gatewayの予約・通信制御の追加開発を終了し、新構成の認証・費用監視・時間制限・停止手順へ置換。厳密な請求上限の保証は引き継がない。
- #56: 独立候補検証とartifact再実行を終了し、通常PR CIの再実行を使う。
- #57: 無人修復を採用せず、利用者がPRコメントで修正を依頼する。
- #63: 説明充実・テンプレート準拠をAIへの指示へ吸収。Draft publisherとCI結果の本文自動同期は採用しない。

#62は個別判断とし、この移行では操作しません。#53・#54・#55は既にclosedで再クローズしません。#30のAction/OS保守、#39と#22〜#27の製品CLI、#32の残項目は一括クローズ対象外です。旧分割実装の [検証記録](../ai-development-validation.md) は歴史的資料として残し、現行構成の保証には使いません。

セットアップ、信頼・資格情報境界の変更、費用、停止・再依頼、切替・切り戻し、公式参照revisionと実動確認の残項目は [OpenCode運用手順](../opencode.md) を参照してください。
