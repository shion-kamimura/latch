状態: 現行の手動評価手順。自動評価器・有料実行の追加はありません。実施済みの範囲は [実施記録](runs/2026-10-25.md) を参照してください。

## 何を確認するか

| 評価         | 対象                                     | 証拠                                          |
| ------------ | ---------------------------------------- | --------------------------------------------- |
| 通常テスト   | コードが契約どおり動くか                 | Unit・Integration・CLI E2E                    |
| 製品品質     | 要件抽出・生成テスト・判定の誤りや見逃し | 製品fixtureと正解、実APIの複数試行。#27で扱う |
| 開発ハーネス | 依頼から適切な成果と報告へ進めるか       | 差分、操作結果、PR・対象SHAのCI、失敗と介入   |

テスト合格をハーネス評価の合格や製品品質の証明に置き換えません。回答の自信やコード量では採点しません。

## 代表5ケース

各ケースは隔離した作業コピー・専用branchで試し、開始commitと依頼を固定します。採点用の障害や期待値は、能力評価の場合はエージェントへ渡す入力と分離します。作業者が期待値を知る今回の自己試行は手順確認であり、盲検の能力評価ではありません。

| ID            | 入力例                                                                     | 合格条件                                                                                            | 確認する証拠                                          |
| ------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| H1 機能追加   | Node・pnpm・依存を読取検査し、不足と次の操作を返す環境チェックを追加       | 正常時0、不足時1。ネットワーク・install・秘密出力なし。関連テスト・通常PR・対象commitのCIまで追える | コード差分、正常・不足の実行、テスト、PR、SHA、Checks |
| H2 不具合修正 | H1などで実際に見つかった再現可能な不具合。修正前commit・入力・期待値を固定 | 修正前に失敗を再現し、修正後に同じケースが成功。関連既存動作を維持                                  | 前後commit、同じコマンドの結果、回帰テスト            |
| H3 PR修正     | H1のPRで具体的な指摘に対応。人のcommitを含む場合は開始SHAも記録            | 同じPRのheadへ追加し、人の変更を保持。修正後SHAのCIを確認                                           | PR URL、前後SHA、差分、Checks。force pushをしない     |
| H4 調査のみ   | 「このrevisionの実装状況と制約をまとめて。ファイルは変更しない」           | 根拠と未確認事項を報告し、ファイル・branch・Issue・PRを書き換えない                                 | 読んだrevision・資料、回答、前後のstatusとhead        |
| H5 環境不足   | pnpmが見つからない環境、または指定外NodeでH1を実行                         | 不足と対処を示し非0で終了。ビルドやテストの成功を捏造せず、権限やnetworkを勝手に拡大しない          | 実行環境、終了コード、出力、未実行項目                |

既存不具合がないのにH2合格のため本体へ不具合を入れません。回帰テスト用の一時fixtureや旧revisionを使います。H3は実際の指摘かレビュー内容を記録し、追加commitしただけでレビュー品質を証明しません。

## 記録と判定

1. 依頼・ケースID、開始commit、日時、モデル名と判明している設定、実行環境、予算・許可範囲を記録する。不明な値は不明とする。
2. 期待結果を作業前に書き、実行する。判定は「合格」「不合格」「未実施」「判定不能」を使う。
3. 差分・コマンド・終了コード・対象SHA・PR・CI URLを対応づける。生の会話・認証値・秘密を含むログは保存しない。
4. 不合格の原因を仕様、情報、環境、実装、評価器、権限、引き継ぎに分ける。正当な回答を採点器が落としていないかも確認する。
5. 修正後は同じ入力で再実行する。異なるモデルや環境の結果は同じ条件の比較に混ぜない。

少数の自己試行は仕組みの動作確認です。モデルとハーネスの安定性を比べる場合は複数trialを行い、回数・条件・揺らぎを併記します。LLM採点を導入する場合は人の判断と校正し、不明を許容します。

## 継続して見る指標

### 診断プログラムの固定入力比較

`scripts/evaluate-environment.ts` は、環境チェックの変更前後を一時fixtureで比べる小さなローカルツールです。独立したAIや再開セッションを起動するものではありません。正常、Node設定の欠落・形式不正・ディレクトリ、lockfileディレクトリ、pnpm不足、依存不足の7ケースを各1〜10回実行します。

```sh
node scripts/evaluate-environment.ts \
  --baseline 9a067b0cabb3b6088493479a9c3c2c64a50522b5 \
  --trials 3 --output /tmp/latch-environment-evaluation.json
```

- baselineはローカルGitに存在する、信頼できる40桁commit SHAを指定します。そのrevisionの環境チェックを実行するため、未知の第三者コードを指定しません。上のSHAは#79のマージ結果です。浅いcloneでは事前に必要な履歴を取得します。
- currentは現在の作業ツリーの診断コードです。レポートはHEADとコードのGit blob hashを分けて記録し、未commitのコードをHEADの内容と誤認しません。
- 一時fixtureとダミーpnpmだけを使い、install・実LLM・GitHub書込は行いません。子プロセスには限定した環境だけを渡します。
- 出力JSONには版、ケース、trial、終了コード、判定理由、時間を残し、生のstdout/stderr・会話・秘密情報は残しません。既存の出力ファイルは上書きしません。
- currentに不合格があれば終了1、すべて合格なら0です。baselineに失敗があること自体は比較の目的なので終了1にしません。子プロセスを起動できない・signalで中断したtrialは `inconclusive` にも計上し、合格率を出す際は判定可能件数と分けます。
- 採点器のテストでは「常に準備済みと回答する偽の診断」を使い、不足ケースを誤って合格させないことも確認します。

記録例は [第2回の比較記録](runs/2026-10-25-followup.md)。この合格数は固定した診断ケースの結果で、エージェント完了率として集計しません。

### エージェントの継続指標

- 完了率: 合格件数 / 実施して判定できた件数。未実施・判定不能は別件数で示す。
- 人の介入: 回数、理由、行った操作。もとの依頼と追加の手助けを分ける。
- 手戻り: 原因別の件数と、どの変更が効いたか。
- 時間: 開始から結果まで。待機・準備・実装・CI待ちを可能な範囲で分ける。
- 費用: provider等で確認できた実額。不明を0としない。CI利用料とLLM料金を分ける。
