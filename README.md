# Latch

AIが生成したコードは、頼んだことを満たしているか。Latchは、要件からテストを計画・生成し、実行結果を証拠として確認するCLIツールです。

ローカルのGit差分と、要件を書いたMarkdownを入力に使います。現在はTypeScript / Node.js・Vitestのプロジェクトを対象に開発中です。

## できること

| コマンド | 役割                                                         |
| -------- | ------------------------------------------------------------ |
| `verify` | 比較先・差分・要件ファイルを読み取り、検証する入力を確認する |
| `plan`   | AIで要件を整理し、既存テスト候補と不足するテストを計画する   |
| `run`    | 不足テストを生成し、一時コピーで実行してレポートを出す       |

レポートでは、要件・テスト・実行ログを対応づけ、成功・失敗・未検証・要件不明確などを区別します。日本語テキストとJSONに対応しています。テスト成功だけでコード全体の正しさを保証するものではなく、通常のCIや人のレビューと合わせて使います。

## 準備する

正式なパッケージ配布はまだありません。リポジトリからビルドして使います。

- Node.js 26 / pnpm 12.14.0 / Git
- AIを使う `plan`・`run` には、Codex CLI 0.163.0とChatGPT PlusまたはProのログイン
- 対応環境はLinux（WSL 2上のUbuntuを含む）。CodexのCLI設定・管理者設定がない環境

対応条件の詳細は [公式CLI接続](docs/official-cli.md) を参照してください。

```sh
npm install --global pnpm@12.14.0
git clone https://github.com/shion-kamimura/latch.git
cd latch
pnpm install --frozen-lockfile
pnpm build
node dist/cli.mjs --help
```

## 最初に入力を確認する

ビルドしたCLIの絶対パスを指定し、調べたいプロジェクトのルートで実行します。`issue.md` は、そのプロジェクト内に置いた要件のMarkdownファイルです。

```sh
node /absolute/path/to/latch/dist/cli.mjs verify \
  --base origin/main --issue-file issue.md
```

`origin/main` を比較先として、コミット済み・未コミットの差分を読み取ります。未追跡ファイルは既定で含めません。`verify` はモデルの呼び出しやテスト実行を行わず、成功は「入力を用意できた」という意味です。

## AIで計画・検証する

次は **[初めてのコードレビュー](docs/review-walkthrough.md)** に進んでください。WSL 2での準備から、ログイン・送信許可の設定、計画の確認、テスト実行、結果の読み方までを案内しています。

1. **送信を許可する**：対象プロジェクトと送信するデータを、リポジトリ外の許可profileに設定する。
2. **`plan` で計画する**：要件の抜けや期待値を確認する。この段階では対象コードを実行しない。
3. **`run` で検証する**：一時コピーでテストを実行し、レポートの証拠と未検証事項を確認する。

認証とモデル通信は公式Codex CLIへ委譲します。生成テストは元のワークツリーへ書き戻しません。実行にはNode.jsの権限制限を使いますが、悪意あるコードの完全な封じ込めを保証するものではありません。

現在はGitHubのIssue・PR URLからの自動取得、Markdownレポートのファイル出力、CI連携、PRへの結果投稿には対応していません。
